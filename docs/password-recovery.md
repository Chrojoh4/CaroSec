# Staff password recovery

The sign-in screen provides Forgot password, an email-only request form, and a verified-link password selection screen. Requests return generic account-independent text. New passwords must match and be 8–128 characters; Supabase enforces its configured password policy as well. The Auth server verifies the user before updating a password, and successful updates request global session sign-out. No service key or database migration is needed.

## Required hosted configuration
In CARO Supabase Authentication → URL Configuration, confirm the Site URL is https://carosec.vercel.app/ and add https://carosec.vercel.app/?auth=recovery to Redirect URLs. Preserve existing authorized production URLs. Configure a production SMTP sender and test delivery. Security email notifications (password/email changed and relevant identity/MFA changes) are separate dashboard settings; this code does not change them.

The browser uses PKCE with tab-local sessionStorage for login tokens. Only namespaced verification keys are shared across same-origin browser tabs, with a one-hour expiry. The emailed link can open in a new tab in the same browser/profile/device. A different browser or device cannot read the verifier; reused/expired links and malformed callbacks show a recovery error. Browsers blocking shared storage retain the older tab-only fallback. Existing tab-local verifiers remain readable for compatibility. Only a successful exchange classified as recovery opens the password form; a query parameter alone does not. Callback codes/errors are removed from the address bar, and password inputs are cleared after save attempts and cancellation.

## Validation
141 automated tests passed with the recovery implementation. Dedicated tests cover generic email requests, redirect destination, invalid inputs, recovery versus ordinary confirmation, expired links, anonymous users, current-user verification, password mismatch, server rejection and session sign-out. The actual hosted screens were tested in a localhost build with fictional Auth responses: request confirmation, verified recovery form and invalid-link handling. No real reset email or password change was performed. Live delivery and real email-link acceptance remain to be tested after dashboard URL and SMTP configuration.

Cross-tab regression tests use the installed official Supabase SDK with a mocked Auth transport: request in tab A, exchange in tab B with its verifier, assert tab A has no session, tab B has its own session, and the consumed verifier is removed. Storage tests cover expiry, key allowlisting, token isolation and blocked-storage fallback. A supplied SDK flow ID is validated, forwarded to exchange and removed from the visible callback URL. The pinned SDK’s experimental overlapping-flow redirect option is now enabled and tested, for signup and recovery. Per-flow URLs select each verifier independently (SDK retains at most five pending flows in one browser; separate participant devices have their own storage). Add the two flow-ID redirect patterns listed in docs/group-account-signup.md.
